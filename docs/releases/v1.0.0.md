# v1.0.0 — ready to plug in

The India Threat Tracker is now something a SOC can subscribe to, not just
read. This release adds native MISP and versioned downloads, two data sources
built for India (CERT-In coverage and lookalike domains), and ATT&CK layers
that show where the detections stop. As before, each piece says how far it has
been tested.

## What you can download

* `india-threat-tracker-detections-v1.0.0.zip`: all 9 rules in Sigma, Splunk,
  Elastic and Wazuh form, with test fixtures, the fraud signals and the
  deployment docs.
* `india-threat-tracker-data-v1.0.0.zip`: every feed and schema, the IOC
  exports, the STIX bundle, the MISP feed and the ATT&CK layers.
* `SHA256SUMS`. The zips are reproducible from the tagged tree.

## New

**Subscribe from MISP.** `misp-feed/` is a native MISP feed: one event per
fraud campaign with indicators, one with the high-relevance KEV CVEs, and one
with new lookalike-domain leads (never marked for blocking). *Tested: the
interop workflow subscribes a real MISP instance to it.*

**CERT-In coverage.** `data/certin-notes.json` collects CERT-In's
vulnerability notes a small, rate-limited batch at a time, and
`data/certin-gap.json` matches every India-relevant KEV entry against them:
did CERT-In publish a note, and how many days before or after CISA listed the
flaw as exploited? "No note" is only claimed once the whole window has been
checked. *The collector's parser is tested against synthetic pages; the first
live runs will show whether CERT-In's real pages read the same way. If not,
the scan stops and says so instead of skipping notes.*

**Lookalike domains.** A daily scan of typo, dictionary (`sbi-kyc`,
`parivahan-challan`) and TLD-swap variants of 15 Indian bank, payment and
government brands. New registrations since the baseline are leads; new ones
are checked against certificate transparency. Defanged, and documented as
leads, not verdicts. *Logic tested offline; DNS and crt.sh only run in
Actions.*

**ATT&CK layers.** `layers/` has Navigator layers for the techniques of the
actors targeting India, the detection coverage over them, and the Mobile
techniques of the fraud campaigns. Every technique id and name in the data is
now checked against ATT&CK v20.0 in CI.

**Use it in your SOC.** [docs/USING.md](../USING.md): recipes for MISP, Wazuh,
Splunk, Elastic, OpenCTI and fraud teams, each marked tested or untested.

**Also since v0.2.0:** hacktivist and ransomware feeds, actor timelines, the
monthly assessment, three more detections (SYSVOL/GPO deployment, Zoho
WorkDrive C2, BitLocker recovery-key reads), tweet drafts for new
India-relevant KEV entries, and a monthly ransomware claim count. See
[CHANGELOG.md](../../CHANGELOG.md).

## Corrections in this release

* The November assessment said UTA0576 *stole* BitLocker keys; the source says
  it *searched for* them. Fixed.
* GhostBat RAT was mapped to T1496, which is not a Mobile ATT&CK technique.
  Removed.

## Still not claimed

Every rule is experimental. The Splunk and Elastic queries have not run on a
live stack. OpenCTI import is untested. India relevance is a keyword
heuristic. Indicators are as reported by the cited sources and are not
re-validated.
