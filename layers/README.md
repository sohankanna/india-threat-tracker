# ATT&CK Navigator layers

Generated by `scripts/build_layers.py` from the tracker's data and detection
rules; rebuilt by the update job and checked in CI. Do not edit by hand.

| Layer | Shows |
|---|---|
| [`india-actors.json`](india-actors.json) | Enterprise techniques used by the state-nexus, ransomware and hacktivist actors tracked here. Darker = more actors |
| [`detection-coverage.json`](detection-coverage.json) | The same techniques, coloured by whether a tracker rule covers them: green (rule tagged with it), amber (only its parent or a sub-technique), red (no rule), blue (a rule, but no tracked actor uses it) |
| [`india-fraud-mobile.json`](india-fraud-mobile.json) | Mobile ATT&CK techniques used by the fake-APK and fraud campaigns |

To view one: open the [ATT&CK Navigator](https://mitre-attack.github.io/attack-navigator/),
choose **Open Existing Layer → Load from URL**, and paste the raw GitHub URL, e.g.

```
https://raw.githubusercontent.com/sohankanna/india-threat-tracker/main/layers/detection-coverage.json
```

The ATT&CK version is in each layer's `versions.attack`. Technique ids are
checked against `config/attack-techniques.json`, refreshed from MITRE with
`scripts/update_attack_ref.py`. The same coverage, as data, is in
`data/attack-coverage.json`.

A rule's ATT&CK tag is its author's claim that it detects *some* procedure of
the technique, not all of them. Green means "there is a rule to start from",
not "covered".
